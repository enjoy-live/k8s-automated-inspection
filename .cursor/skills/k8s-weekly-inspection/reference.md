## 写作契约

渲染器根据标记上色。不要在 Markdown 里写 `<font>`、HTML 或色值。

1. **本周重点**写成引用块里的有序列表。渲染为红色加粗，标题「本周重点」也是红色。一条事实一行，通常 2 到 4 条。没有计划外故障时只写一条：`本周期无计划外故障`。

```markdown
> **本周重点：**
> 1. 第一条最重要的事实
> 2. 第二条事实
> 3. 需要管理层知道的未完成事项
```

2. **并列数据用有序列表** `1. 2. 3.`。包括：一个字段下的多条名单、证据、建议、下周计划、缺失项、组件状态子项。渲染器保留你写的序号。
3. **字段定义仍用无序列表**，一行一个字段：`- **报告周期：** ...`、`- 集群可用率 (SLA)：...`。这种行不是排名，不要改成序号。
4. **节点详情必须有「根分区」列**，填根文件系统使用率，格式 `xx.x%`（百分号，保留 1 位小数）。口径见第 2 节。
5. **严重**小节标题含 `【严重】`。标题渲染为红色。该小节内以 `现象：`、`结论：`、`影响：` 开头的行是核心行，整行红色。证据和操作步骤保持正文色，除非本行触发第 7 条。
6. **警告**写在表格的级别格，整格只能是 `警告` 或 `warning`。该行全部单元格红色，并铺浅红底。列表警告写成 `1. 【警告】...`，整行红色。`提示`、`info`、`none` 不上红色。
7. **异常、复发**：去掉否定短语后，行内仍有「异常」或「复发」时，正文整行红色；表格则整行红字加浅红底。否定短语包括「无异常」「未发现异常」「没有异常」「无复发」「未复发」「不再复发」。写「本周期未发现异常」不会标红。同一行既有否定又有肯定时仍然标红，例如「上期无复发，本期复发」。
8. **第 6 节始终保留。** 有下一周能推进的具体动作就写有序列表；没有就只写 `1. 暂无安排`。
9. **上期工作计划落实情况**：上一份周报第 6 节有可执行事项时，用表格逐条给状态；没有则用一句话说明，不要造空表。

严重和警告不要互换标记。严重是已经造成中断、数据风险或硬件故障仍未根除。警告是持续告警、临近阈值、多期未执行但本周期没有新的中断。

## 口径

资源汇总表：

| 列 | 怎么填 |
|---|---|
| 峰值利用率 | 周期内 Prometheus 最大值 |
| 周期平均利用率 | 周期内平均值。列名用「周期平均」，不要再写「高峰期平均」 |
| 峰值时剩余可用量 | 峰值时刻还剩多少。存储行写 Bound 容量，并注明 Released 待回收量 |

节点详情表：

| 列 | 怎么填 |
|---|---|
| CPU | 节点容量，如 `56c`。不要填 CPU 利用率 |
| 内存使用 | 巡检时刻 `kubectl top nodes` 的内存百分比，如 `27%` |
| GPU | 型号、数量和显存。不要填 GPU 利用率 |
| 当前 Pod 数 | 巡检时刻该节点 Running Pod 数 |
| 根分区 | 根文件系统使用率，如 `48.5%` |

内存使用和根分区都是巡检时刻的瞬时值，不是周期峰值。表下用一句话写明采样时间。某个节点没采到就填 `未采集`，不要留空，也不要编百分比。

根分区使用这条 PromQL，在 Prometheus port-forward 之后执行，原始 JSON 保存到证据目录 `rootfs.json`。`nodename` 对不上节点名时，用 `node_uname_info` 的 instance 和节点 InternalIP 对照，对照过程写进证据，不要猜节点。

```promql
100 * (
  1 - (
    max by (nodename) (
      node_filesystem_avail_bytes{mountpoint="/",fstype!~"tmpfs|overlay|squashfs|ramfs"}
      * on(instance) group_left(nodename) node_uname_info
    )
    /
    max by (nodename) (
      node_filesystem_size_bytes{mountpoint="/",fstype!~"tmpfs|overlay|squashfs|ramfs"}
      * on(instance) group_left(nodename) node_uname_info
    )
  )
)
```

禁止用 `kubectl debug`、`kubectl exec` 进新 Pod 或在节点上临时跑 `df` 来补根分区。查询失败就在表里写 `未采集`，并在缺失项说明。

GPU 带载表和 PV 状态表采到数据才建表。没采到就保留小标题，下面写「本周期未采集到」和原因，不要留空表，也不要删标题。

PVC「用途」列只写名称、命名空间、创建时间能够证明的信息。证明不了就写「未证实」。

## 只读命令

先建证据目录，再把输出重定向进去。下面的 `START` / `END` 换成周期起止的 RFC3339（+08:00）。

```bash
EVID=/home/storage/k8s-weekly-inspection/output/evidence-YYYYMMDD
mkdir -p "$EVID"
kubectl config current-context > "$EVID/context.txt"
kubectl get nodes -o wide > "$EVID/nodes.txt"
kubectl top nodes > "$EVID/top-nodes.txt"
kubectl get pods -A -o wide > "$EVID/pods.txt"
kubectl get deploy,sts,ds -A > "$EVID/workloads.txt"
kubectl get events -A --field-selector type=Warning > "$EVID/warning-events.txt"
kubectl get pvc,pv -A > "$EVID/storage.txt"
kubectl get svc,ingress -A > "$EVID/network.txt"
kubectl get notebooks.kubeflow.org -A > "$EVID/notebooks.txt"
kubectl get inferenceservices.serving.kserve.io -A > "$EVID/kserve.txt"
kubectl get workflows.argoproj.io -A > "$EVID/workflows.txt"
kubectl get backups.velero.io -A > "$EVID/velero.txt"
```

资源明细用 json，在本地按周期过滤，不要把 Token、Secret data 写进证据文件：

```bash
kubectl get nodes -o json > "$EVID/nodes.json"
kubectl get pods -A -o json > "$EVID/pods.json"
kubectl get events -A -o json > "$EVID/events.json"
kubectl get backups.velero.io -A -o json > "$EVID/velero.json"
```

Prometheus 只读查询沿用现有 Service，不修改监控对象：

```bash
kubectl -n monitoring port-forward svc/prometheus-kube-prometheus-prometheus 19093:9090
```

根分区查询把 JSON 存到 `$EVID/rootfs.json`。查询结束后结束这个本地 `port-forward` 进程。查询失败就在周报第 2 节写明缺失，保留 `kubectl top nodes` 的即时值，并注明它不是周期峰值。

证书、GPU、节点日志只有在不创建工作负载的前提下读取。命令失败时记录退出码和缺失影响，不要改用会新建 Pod 的方式补数据。

## 交付检查

- 六个章节标题都在，顺序未改
- 本周重点是有序列表，每条都以 `> ` 开头
- 并列名单、证据、建议、计划、缺失项用 `1. 2. 3.`；字段定义仍用 `-`
- 节点详情含「根分区」，值是百分数或 `未采集`
- 资源表列名是「峰值利用率 / 周期平均利用率 / 峰值时剩余可用量」
- 严重标题含 `【严重】`，并且有「现象」和「影响」行
- 警告的级别格只有 `警告` 或 `warning`；列表警告带 `【警告】`
- 出现「异常」或「复发」的行没有被否定短语包掉
- 有上期可执行计划时，落实表覆盖每一条；没有时有一句说明
- 第 6 节存在；没有具体动作时只有「暂无安排」
- 周期、生成时间、数据来源、证据目录都在
- Markdown 和 PDF 都在 `output/` 下，文件名日期是周期结束日
- 证据目录里能找到对应命令输出，包括 `rootfs.json` 或失败记录
- Markdown 里没有 HTML 颜色
